# Личный гардероб

Мобильный сайт по [спецификации](docs/wardrobe-mvp-spec.md). Без сборки и серверного приложения: обычные HTML, CSS и JavaScript.

## Запуск

Нужны Python 3 и Node.js 22+ (для тестов).

```sh
npm start
```

Открыть [локальный сайт](http://127.0.0.1:5173). Для работы ES modules и IndexedDB использовать HTTP, а не открывать `index.html` как файл. На телефоне сайт можно разместить на собственном HTTPS-сервере как статические файлы: `index.html`, `src/`, `looks/looks.json`, `looks/two-looks-preview.png`, `clothes_photos/`. Исходные фотографии при этом станут доступны серверу и его посетителям; локальный запуск ничего не публикует.

## Проверка

```sh
npm ci
npx playwright install chromium
npm run check
```

Если установлен Google Chrome, вместо скачивания Chromium:

```sh
PW_BROWSER_CHANNEL=chrome npm run check
```

Unit-тесты используют встроенный Node test runner. Playwright проверяет настоящий браузер и IndexedDB; ответы погоды фиксированы, поэтому тесты не зависят от сети. Тестовый сервер запускается и останавливается автоматически. Перед проверкой остановить запущенный `npm start`, чтобы освободить порт 5173.

## Что работает

- 70 описанных вещей и 53 готовых сочетания из `looks/looks.json` доступны сразу. Все 70 вещей из каталога участвуют в готовых сочетаниях; новые загруженные фото пока не распознаются.
- Одна обязательная вещь, два повода; повседневные сочетания упорядочены по приоритету удобства из готового lookbook, вечерние — по театральным сценариям. Погода меняет приоритет слоёв и советы; теплота и посадка не выводятся из фото.
- Для сочетаний 1 и 3 показаны соответствующие половины существующего коллажа. Для остальных — исходные фотографии вещей. Рекомендации купить/добавить неучтённые аксессуары не включены в состав образов.
- Автопогода для Москвы (город указан в интерфейсе); можно запросить геопозицию или задать погоду вручную. Только координаты уходят в бесплатный Open-Meteo. При ошибке ручной ввод доступен сразу.
- Фото с телефона/камеры → предпросмотр → сохранение в IndexedDB. Они остаются после перезагрузки в том же браузере и на том же адресе, помечаются «Пока без подбора» и не используются в образах.
- Нечитаемые фото, файлы более 20 МБ и ошибки хранения сопровождаются сообщением. Поддержка HEIC зависит от браузера; при ошибке можно выбрать JPEG, PNG или WebP.

Синхронизации, резервных копий, распознавания и создания коллажей нет. Очистка данных браузера может удалить добавленные фото. Серверной отправки фото, аналитики и платных сервисов нет.

## GitHub Pages

Адрес сайта: https://ivan-karavan.github.io/beauty_app/.

Workflow `.github/workflows/deploy.yml` запускается при push в `main` или вручную.
Он прогоняет unit-тесты, собирает `dist/`, проверяет его браузерными тестами по вложенному пути `/dist/` и публикует на GitHub Pages.
Если тесты не проходят, новая версия не публикуется. В Settings → Pages источник публикации — GitHub Actions.

```sh
npm run build
npm run test:prod
```

В `dist/` входят только HTML, runtime-модули/CSS, каталог, используемый коллаж и все 70 фотографий из каталога.
Тесты, документация, зависимости и старый lookbook в публикацию не попадают.
Исходные фотографии и коллажи сайта публичны; новые загруженные фото остаются в IndexedDB браузера.
Данные с localhost не переносятся автоматически на адрес GitHub Pages.

При ручном вводе погоды кнопка «+ / −» меняет знак температуры, даже если на телефонной клавиатуре нет минуса.

Ручная погода сохраняется в этом браузере после перезагрузки. Кнопка «Вернуть автопогоду» отменяет сохранённый ручной выбор. При недоступном хранилище показывается сообщение; выбор действует до перезагрузки.
